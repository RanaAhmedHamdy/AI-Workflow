## Approved scope

## Binding design properties

State which properties are authoritative for implementation, as applicable:

- visual hierarchy and composition;
- grouping and section order;
- relative component sizing and action placement;
- spacing rhythm;
- typography hierarchy;
- color/tokens, borders, radii, elevation;
- icon roles/placement;
- interaction/state behavior;
- responsive/form-factor variants;
- localization/RTL/accessibility behavior where explicitly designed.

## Permitted adaptations

Material divergence is permitted only when required by documented platform behavior, accessibility, localization/RTL, supported window geometry, or explicit owner approval. “More native,” framework defaults, or implementation convenience are not sufficient reasons for redesign.

## Downstream rule

A design-bound UI task must identify and inspect the exact approved visual artifact before UI implementation. Screen contracts/design-system documents supplement but do not replace visual inspection.

## Supersession

External revisions do not silently replace this authority. Record owner approval before changing the canonical approved revision.
