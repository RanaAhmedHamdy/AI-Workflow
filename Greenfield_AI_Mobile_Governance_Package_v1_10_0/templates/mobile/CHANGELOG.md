# Changelog

## 1.10.0

- Added design-bound UI Design Lock fields to both iOS and Android plan/task templates.
- Required pre-code inspection of exact approved visuals for design-bound UI while keeping screenshot/fidelity review optional by default.
- Clarified optional design-tool connectors and repository-approved revision authority.
- Added readiness support for inspectable exact design artifacts and permitted adaptations.

## 1.9.1

- Added Feature Input provenance and clarification tracking.
- Clarified that GrillMe-style clarification may refine the bounded intake but must be normalized into reviewed Feature Input before contract authoring.
- Preserved PRD/product authority and explicit owner decisions as the source of material product behavior.

## 1.9

- Added evidence execution timing enforcement across skills, not just templates.
- Added evidence reuse and compact long-running verification summaries.
- Added representative risk-based runtime matrices and manual final validation guidance.
- Added coherent vertical task guidance to reduce ceremonial task splitting.
- Added convergence blocker taxonomy and readiness spot-check model.
- Preserved all behavior, architecture, mutation-propagation, origin-aware navigation, and default-to-COMPLEX safeguards.


## 1.8

- Split implementation plan/task templates into iOS/iPadOS and Android variants.
- Kept Feature Input, Feature Contract, readiness audit, and readiness report shared/mobile.
- Neutralized Android-specific wording in the shared Feature Contract.
- Added verification timing (`TASK-CLOSURE`, `FEATURE-CONVERGENCE`, `FINAL-READINESS`) and blocking scope/cost classification.
- Added evidence reuse: one valid artifact may satisfy multiple verification rows.
- Added convergence blocker taxonomy so CI/evidence/docs/repository-state blockers are not mislabeled as implementation defects.
- Preserved default-to-COMPLEX behavior when platform complexity classification is not executed or is missing/invalid/stale.
