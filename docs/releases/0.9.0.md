# AI-Workflow 0.9.0

## What this is

AI-Workflow is a pre-v1 set of repository-owned workflows and specialist
procedures for AI-assisted native Android and iOS development. It supports new
and existing repositories, with deterministic routing from stated mobile
concerns to bounded checks.

## Why this release exists

`0.9.0` is the first external-evaluation release. It is intended to be
challenged by Android and iOS developers before the project makes a v1
compatibility promise.

## Highlights

- Android and iOS workflows for Greenfield and Brownfield repositories.
- `skills`, `safety`, `feature`, and `full` adoption profiles; Safety is the
  recommended starting point.
- Deterministic fact-based routing across the checked-in concern registry.
- Manifest-backed install, status, update, dry-run, and uninstall lifecycle with
  unmanaged-collision protection, modified-file preservation, traversal/symlink
  checks, and staged rollback.
- Native Android and iOS profile-refresh fixtures with explicit evidence limits.
- A compact SMALL path with proportional escalation to STANDARD or COMPLEX.

## Quick start

After the tag is public and the package is published:

```bash
uvx --from ai-workflow==0.9.0 ai-workflow profiles
uvx --from ai-workflow==0.9.0 ai-workflow brownfield --platform android --profile safety --target /path/to/existing-app
```

The reproducible GitHub-tag alternative is:

```bash
uvx --from git+https://github.com/RanaAhmedHamdy/AI-Workflow.git@v0.9.0 ai-workflow profiles
```

## Important limitations

This is pre-v1 software and external feedback is wanted. Codex consumption has
been manually reviewed; Claude Code and Copilot coding-agent interoperability
is not certified. Native fixtures are bounded demonstrations, not production
certification or proof of every runtime/device behavior. AI-Workflow does not
authorize changes, replace engineering owners, or certify releases.

## Feedback wanted

Please report routing false positives/negatives, profile friction, missing
Android or iOS safeguards, installer lifecycle issues, and whether the
Brownfield path is practical on a real repository.
